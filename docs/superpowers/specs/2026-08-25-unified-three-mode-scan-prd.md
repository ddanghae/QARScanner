# QARScanner 3개 모드 통합 스캔 PRD

작성일: 2026-08-25
상태: 승인 대기
대상 저장소: `QARScanner-main-pump-fade-20260824`

## 1. 문제

현재 사용자는 `급락 반등`, `조기 포착`, `급등 후 급락` 모드를 각각 선택하고 스캔을 따로 실행해야 한다. 세 전략의 후보를 한 번에 확인하려면 설정 변경과 재스캔을 세 번 반복해야 하며, 결과를 비교할 때 어떤 전략에서 나온 후보인지 한눈에 구분하기 어렵다.

## 2. 성공 기준

1. 사용자가 `전체 스캔`을 선택하고 `스캔 시작`을 한 번 누르면 세 모드가 모두 실행된다.
2. 결과 화면에서 세 모드의 결과를 한 번에 볼 수 있다.
3. 모든 결과에 다음 출처 배지 중 하나가 명확히 표시된다.
   - `급락 반등`
   - `조기 포착`
   - `급등 후 급락`
4. 동일 종목이 둘 이상의 모드에서 검출되면 각 검출을 별도 행으로 유지한다. 모드마다 방향, 점수, 단계, 진입 계획의 의미가 다르기 때문이다.
5. 세 모드의 점수를 하나의 공통 점수처럼 섞어 정렬하지 않는다. 결과는 모드별로 묶고 각 모드의 기존 순위를 유지한다.
6. 기존 개별 모드 선택과 실행 방식은 그대로 동작한다.
7. 마감봉 기본값, 실시간 예상 표시, 미래 봉 차단, SHORT 방향성 등 기존 리페인트 방지 규칙을 유지한다.
8. 전체 테스트와 신규 통합 테스트가 통과한다.

## 3. 범위

### 포함

- 스캔 모드 선택에 `전체 스캔` 추가
- 한 번의 사용자 실행으로 세 파이프라인 순차 실행
- 공통 종목 목록과 24시간 티커 응답 재사용
- 통합 진행 상태에 현재 실행 중인 모드 표시
- 결과 상단에 모드별 검출 개수 요약
- 결과를 모드별 섹션으로 묶어서 한 화면에 표시
- 테이블과 모바일 카드 모두에 스캐너 출처 배지 표시
- 상세 패널에도 스캐너 출처 표시
- 개별 모드 필터 및 기존 기능 유지
- 자동 갱신 시에도 선택된 `전체 스캔`을 한 번의 주기로 실행
- 결정적 통합 테스트와 기존 회귀 테스트 추가/실행
- README, PROGRESS, 서비스워커 캐시 버전 갱신

### 제외

- 점수 계산식, 임계값, 단계 의미 변경
- 세 전략의 점수를 공통 확률로 보정
- 병렬 실행으로 Binance 요청을 급격히 늘리는 구조
- 자동 주문, 계좌 연결, 개인 API 키
- 백엔드 또는 데이터베이스 도입
- 페이퍼 기록 형식 변경
- 기존 연구 모델 재학습 또는 성과 개선 주장

## 4. 제약 조건

- 정적 GitHub Pages와 Vanilla HTML/CSS/JS 구조를 유지한다.
- Binance 공개 REST API만 사용한다.
- 현재 각 파이프라인의 닫힌 캔들 처리와 시간 정렬을 유지한다.
- `pump_fade` 점수는 확률로 표시하지 않는다.
- 전체 스캔은 API 과호출과 가변 전역 설정 충돌을 피하기 위해 세 모드를 순차 실행한다.
- 중간 모드 하나가 실패해도 가능한 경우 나머지 모드는 계속 실행하고, 실패한 모드만 오류 상태로 표시한다.
- 사용자가 중단하면 현재 요청과 남은 모드 실행을 모두 중단한다.

## 5. 사용자 경험

1. 모드 선택의 첫 항목에 `전체 스캔 (3개 모드)`를 추가한다.
2. `스캔 시작`을 누르면 진행 문구가 `급락 반등 1/3`, `조기 포착 2/3`, `급등 후 급락 3/3`처럼 현재 위치를 보여준다.
3. 완료 후 상단에 `급락 반등 N · 조기 포착 N · 급등 후 급락 N` 요약을 표시한다.
4. 결과는 같은 화면에서 다음 세 섹션으로 표시한다.
   - 급락 반등
   - 조기 포착
   - 급등 후 급락
5. 각 행과 카드에 모드 배지를 반복 표시하여 정렬·반응형 화면에서도 출처가 사라지지 않게 한다.
6. 동일 종목이 여러 모드에 나오면 각 섹션에 각각 표시한다.

## 6. 구현 계획

### Builder

1. 기존 `runScan`에서 공통 준비와 모드별 파이프라인 실행을 분리한다.
2. 기존 개별 모드 경로를 그대로 호출할 수 있는 내부 실행 함수로 정리한다.
3. `all` 모드는 공통 universe/ticker 데이터를 재사용하며 세 모드를 순차 실행한다.
4. 결과 객체에 기존 `scanMode` 값을 보존하고 reversal 결과에는 명시적으로 `scanMode: "reversal"`을 붙인다.
5. 통합 결과 상태와 모드별 오류/개수 정보를 저장한다.
6. 대시보드를 모드별 섹션과 출처 배지로 렌더링한다.

### Auditor

1. 전역 `state.settings.scanMode`를 실행 중 임시 변경하지 않는지 확인한다.
2. 현재 캔들 포함 설정과 닫힌 캔들 경계가 세 모드에서 동일하게 유지되는지 확인한다.
3. `pump_fade`의 15분 신호 시각 이후 5분봉이 섞이지 않는지 확인한다.
4. 동일 종목의 결과 객체가 서로 덮어써지지 않는지 확인한다.
5. 공통 API 응답 재사용으로 데이터 기준 시각이 모드마다 달라지지 않는지 확인한다.
6. 자동 갱신, 중단, 오류 복구, 필터, 상세 패널, 페이퍼 기록 회귀를 확인한다.

### Tester

1. `all` 선택 시 세 파이프라인이 정확히 한 번씩 실행되는 테스트
2. 결과에 올바른 `scanMode`가 붙는 테스트
3. 동일 심볼의 다중 모드 결과가 보존되는 테스트
4. 모드별 순위가 유지되고 전역 점수 정렬이 적용되지 않는 테스트
5. 한 모드 실패 시 다른 모드 결과가 유지되는 테스트
6. 중단 시 남은 모드가 실행되지 않는 테스트
7. 개별 모드 회귀 테스트
8. `node tests/run.js` 및 변경 JavaScript 구문 검사

### Integrator

1. 중복 API 호출과 죽은 UI 제어를 재검토한다.
2. README 사용법과 기능 설명을 갱신한다.
3. PROGRESS에 변경 사실과 검증 결과를 추가한다.
4. 서비스워커 캐시 버전을 올린다.
5. 변경 파일, 테스트 결과, 리페인트/API 요청 위험, 남은 한계를 보고한다.

## 7. 미해결 질문 및 기본 결정안

1. **결과 표시 방식**: 기본 결정은 단일 점수순 목록이 아니라 한 화면 안의 모드별 3개 섹션이다. 세 모드 점수의 의미가 달라 직접 비교하면 오해를 만든다.
2. **중복 종목**: 기본 결정은 합치지 않고 모드별 별도 결과로 표시한다. 합치면 방향과 진입 계획이 충돌할 수 있다.
3. **실행 방식**: 기본 결정은 순차 실행이다. 한 번의 클릭이라는 사용자 경험은 유지하면서 Binance 요청 폭증과 전역 상태 충돌을 피한다.
4. **기본 선택값**: 기존 사용 경험을 보존하기 위해 앱 최초 기본값은 `급락 반등`을 유지하고, 사용자가 `전체 스캔`을 선택하면 그 설정을 저장한다.
