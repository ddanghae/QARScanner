# QAR 연구실

기출문제(시세)를 모으고, 기존 전략과 CRT 조건을 같은 시험에 넣는 로컬 연구 환경. 실제 주문이나 운영 전략 자동 교체 기능은 없다. Node.js 20 이상만 필요하며 외부 패키지 설치와 개인 API 키는 필요 없다.

## 빠른 시작 — 저장소 루트에서

```powershell
.\lab.cmd doctor
node --test research/lab/tests.mjs
.\lab.cmd all
.\lab.cmd serve
```

마지막 명령을 실행한 상태에서 http://127.0.0.1:8876 을 연다. 서버는 Ctrl+C로 종료한다. 초기 설정은 BTC/ETH, 2026-07-18부터 2026-09-16 UTC 자정 직전까지의 **동작 확인용 작은 실험**이다. 전략 성능을 판정할 충분한 표본을 보장하지 않는다.

`collect`는 시세를 받으며, `run`은 저장된 파일로 오프라인 계산한다. `all`은 둘을 차례로 실행한다. 재수집 시 정상 저장된 종목은 재사용한다. 특정 종목 수집이 중단됐다면 해당 종목부터 다시 받는다. 다운로드는 순차 처리하고 거래소 제한에 걸리면 중단/재시도한다.

## 폴더

- `research/lab/`: 버전 관리되는 실행 코드·설정·테스트.
- `lab-data/<dataset id>/`: 압축 JSON 5분봉, 상장일 등 메타데이터, 누락/중복 검사 결과, SHA-256 체크섬. Git 제외.
- `lab-runs/<run id>/`: 설정과 코드 해시, 분할 시각, HTML 성적표, 비교 CSV, 거래별 JSONL, 원본 JSON. 실행마다 새 폴더. Git 제외.
- `lab-paper/snapshots/`: 관측 시점의 입력 캔들·신호·계획·확률·모델/코드 버전. 기존 파일 덮어쓰기 금지.
- `lab-paper/outcomes/`: 이후에 판정한 결말. 원본 관측과 분리. Git 제외.

압축 JSON은 추가 설치 없이 재현하기 위해 선택했다. 20~50종목×1~2년으로 확대할 때는 저장 공간과 실행 시간을 먼저 확인한다. 원본 전체는 GitHub Pages에 올리지 않는다.

## 설정 확대

`research/lab/config.json`을 별도 이름으로 복사·편집하고 다음처럼 지정한다.

```powershell
.\lab.cmd collect --config research/lab/my-study.json
.\lab.cmd run --config research/lab/my-study.json
```

- `symbols`: 중복 없는 USDT 무기한 종목. 거래량·변동성 그룹을 사전에 정해 고른다. 결과를 본 뒤 잘 된 코인만 골라서는 안 된다.
- `start`/`end`: UTC 자정, 끝 날짜 미포함. 선택 종목들이 전부 존재하는 기간이어야 한다. 상장 전/중간 누락을 0으로 채우지 않고 수집 실패로 보고한다.
- `warmupDays`: 최소 40일. EMA200 등 계산 이력 확보용이며 성적 집계에서는 제외.
- `evaluationMinutes`: 기본 5분. 크게 설정하면 짧은 CRT 신호를 놓칠 수 있다.
- `holdHours`: 모든 전략에 적용하는 최대 보유시간. 기본 24시간은 비교 실험 가정이며 기존 조기 전략의 원래 15일 제한과 다르다.
- `feeBpsPerSide`/`slippageBpsPerSide`: 각 방향 비용. 기본 각각 5bp → 왕복 총 0.2%. 펀딩·시장 충격은 미포함.
- `splitFractions`: 준비 구간 뒤 시간순 개발/검증/시험 비중. 기본 60/20/20. 경계 앞 최대 보유시간만큼은 제외한다.
- `minResolvedTrades`: 성적표의 표본 부족 표시에 쓰는 최소값. 이 개수를 넘었다고 수익성이 입증되는 것은 아니다.

## 무엇을 비교하나

반등·조기·급등 후 급락 각각의 원본 조건과, 같은 방향의 CRT 확인을 추가한 조건을 비교한다. 이 쌍은 같은 손절·목표를 사용한다. 별도로 CRT 단독 조건은 전용 계획을 사용한다.

라이브 계산 함수를 재사용하지만 전체 시장 거래대금 순위·상위 N개 표시·모든 동시보유 자금 제한은 재현하지 않는다. 선택 코인의 조건을 시험하는 환경이다. 조기 포착은 원래 BTC/ETH 등 대형 코인을 제외하므로 초기 표본에서 0건이 정상이다. OI·펀딩 이력은 현재 채점에 사용되지 않는 보조 항목이므로 연구에서는 비워두며 펀딩 비용도 포함하지 않는다.

마지막 봉이 닫힌 뒤 다음 5분봉 시가에 모의 진입한다. 원래 앱의 지정가 체결 재현이 아니다. 손절·목표는 신호 당시 가격 수준을 유지하고 시가가 이미 목표를 넘었으면 계획 불가 처리한다. 목표1 부분 청산 후 본전 이동 순서를 봉 하나로 알 수 없으면 `AMBIGUOUS`다. 가격 공백으로 손절을 뛰어넘으면 더 나쁜 시가를 사용한다. 신규 진입은 전략별·코인별 최대 한 개다.

승률·평균 R은 결말이 확정된 거래만 사용하므로 모호/미완료 건수를 반드시 함께 본다. 모호 비율이 높으면 이 평균 자체가 편향될 수 있다. 손실 없는 경우 PF는 공란이다. 성적표의 거래순 누적 R 낙폭은 실제 포트폴리오 최대 낙폭이 아니다.

## 실시간 모의 관측

```powershell
.\lab.cmd paper-snapshot
# 최대 보유기간이 지난 후
.\lab.cmd paper-settle
```

스냅샷은 공개 API만 읽는다. 관측 시점 **이후 최초 5분봉 시가**를 진입 기준으로 삼아 이미 지나간 가격에 진입했다고 기록하지 않는다. 실행 때마다 별도의 관측을 저장하며 관측 간 중복 후보는 독립 실험이다. 관측 횟수를 실제 거래 횟수로 합산하지 않는다. 자동 반복은 아직 실행하지 않는다. 필요할 때 이 명령을 PC 스케줄러에 연결할 수 있다.

만기 전 결말은 `pending`으로 두고, 데이터가 빠지면 다음 실행에서 재시도한다. 확률은 당시 수치와 입력을 보존하지만 **현재 paper-settle은 매매 계획만 채점**한다. 24시간 확률의 보정 오차를 추적하는 집계는 다음 확장 과제다.

## 신뢰성 장치와 한계

미래 봉은 신호 함수에 주지 않는다. 4시간·1시간·15분은 같은 5분 자료에서 UTC 경계로 집계하고, 미완성/누락 묶음은 만들지 않는다. 상장일에 따른 조기 점수는 실제 관측 당시 시각으로 계산한다. 파라미터 자동 탐색을 하지 않으며 기준 설정과 코드 파일별 해시를 저장한다.

조기포착은 새 4시간 마감봉이 열린 첫 5분 평가에서만 한 번 기록한다. 같은 4시간 마감봉을 다음 5분 평가에서 다시 세지 않아 신호 수와 성능이 부풀지 않게 한다.

현재 거래소 종목 목록에서 선택한 자료이므로 상장폐지 편향은 해결하지 못했다. 이를 알고 있는 상태의 실험 환경이지 전체 시장 수익성 인증 도구가 아니다. 연구 결과만으로 자동 주문하거나 운영 점수를 변경하지 않는다.
