# pump_fade 세 번째 스캔 모드 PRD

- 상태: 승인·구현 완료
- 승인일: 2026-08-24
- 작업 순서: Builder → Auditor → Tester → Integrator

## 문제

기존 `reversal`과 `early`만으로는 급등 종목의 상승 소진과 실제 하락 구조전환을 독립적으로 좁힐 수 없다. 단순 상승률만으로 숏 후보를 만들면 상승 지속 구간을 너무 일찍 역추세로 잡을 위험이 있다.

## 성공 기준

- `scanMode: "pump_fade"`가 기존 두 모드와 분리된 SHORT 전용 파이프라인으로 동작한다.
- 급등 뒤 거래량 클라이맥스, 고점 거절, Taker Buy 소진, 15분 EMA20/VWAP 이탈, 5분 구조 붕괴를 과거·현재 마감봉만으로 계산한다.
- 기본값은 진행 중 캔들을 제외하고, 명시적 opt-in만 `provisional` 결과를 허용한다.
- 1~3단계, 100점 규칙, -25점 늦은 진입 감점, 45점 표시 컷, 최종 상위 5개를 구현한다.
- SHORT 손절은 진입가 위, TP1/2/3은 진입가 아래이며 손절 거리 8% 이상은 무효 또는 경고 처리한다.
- 오프라인 연구에서 동일 봉 목표/손절을 `AMBIGUOUS`로 분리하고 시간순 60/20/20 및 6시간 purge를 적용한다.
- 전체 회귀 테스트가 통과하고 lookahead, repaint, data leakage, API 호출량을 별도 감사한다.

## 범위

- 새 순수 코어 `js/core/pump-fade.js`
- 설정·상태·스캔 컨트롤러의 전용 분기
- 모드 선택, SHORT 잠금, 단계·점수·상세 표시
- 서비스워커 캐시 버전과 앱 셸 갱신
- 결정적 단위·회귀 테스트
- 재현 가능한 threshold sweep 연구 CLI와 순수 라벨/요약 모듈
- README와 진행 기록 갱신

## 범위 밖

- 자동 주문, 계정·포지션·레버리지·개인 API 키
- TradingView Pine에 pump_fade 판정을 포팅하거나 QAR 점수를 전달하는 작업
- 백테스트 결과가 없는 상태에서 임계값·가중치를 자동 최적화하거나 성과로 홍보하는 작업
- 고정 과거 데이터셋 수집과 실제 성과 결론

## 제약 조건

- 기존 `reversal`/`early` 계산 계약과 Pine v3.3/v3.4 파일을 변경하지 않는다.
- 기존 유동성 유니버스를 사용하고, 성능을 이유로 승인되지 않은 후보 상한을 추가하지 않는다.
- 사후 결과 캔들은 연구 라벨러만 소비하며 운영 코어는 연구 모듈을 import하지 않는다.
- 누락·비정상 데이터, 불명확한 동일 봉 순서, 불완전한 결과 구간은 실패-폐쇄한다.
- 점수와 임계값은 UI와 문서에서 `EXPERIMENTAL`로 명시하고 성공 확률로 표현하지 않는다.

## 구현 계획

1. Builder: 설정, 코어 계산, 전용 파이프라인, UI, 서비스워커, 연구 도구, 테스트를 구현한다.
2. Auditor: prefix 불변성, 캔들 마감 여부, 시각 정렬, 사후 라벨 격리, 동일 봉 모호성, SHORT 가격 방향, API 요청 범위를 감사한다.
3. Tester: 전체 테스트, 전체 JS/MJS 구문, 연구 CLI·재현성, 서비스워커 경로를 검증한다.
4. Integrator: 사용자 문서와 진행 기록을 갱신하고 최종 diff와 기존 파일 보존 여부를 확인한다.

## 확인된 저장소 불일치

요구문에는 `js/ui/format.js`의 `planMoney()`와 청산가 수정을 요청했지만, 현재 파일과 전체 Git 이력에는 `planMoney`, `liqDropPct`, 청산가 표시 계약이 존재하지 않는다. 존재하지 않는 레버리지·청산 모델을 임의로 만들면 공개 데이터·신호 전용 범위를 벗어나므로, 승인된 범위에서는 이를 추가하지 않는다. 대신 실제로 존재하는 LONG 계획 회귀와 새 SHORT stop/TP 방향을 테스트한다.
