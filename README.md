# QAR Scenario Scanner

Binance USDⓈ-M Futures에서 급락 반등, 조기 포착, 급등 후 하락 전환 후보를 좁히는 스캐너.
GitHub Pages에서 실행되는 **정적 웹앱**입니다. 빌드 과정·백엔드·개인 API 키가 필요 없습니다.

> ⚠️ 기술적 참고용 도구입니다. 자동 주문 기능이 없으며, 표시되는 진입/손절/목표가는
> 실제 주문 가격이 아닌 계산된 참고 구간입니다. 투자 판단의 책임은 사용자에게 있습니다.

> 작업을 다른 컴퓨터에서 이어가려면 [PROGRESS.md](PROGRESS.md) 먼저 읽을 것.

## 무엇을 하는가

### 리빌딩 2단계 — 의사결정 체크리스트 + 저널 운영성

- 기존 점수와 후보 순서는 그대로 두고 계획 유효성, 진입 단계, BTC 시장국면, 24시간 방향 전망, CRT 확인, 후보 간 상관을 한 화면에서 점검합니다.
- 결과는 `검토 후보`·`확인 대기`·`리스크 높음`으로 표시됩니다. 성공 확률이나 매매 지시가 아니라 서로 충돌하는 조건을 놓치지 않기 위한 체크리스트입니다.
- Forward Paper Ledger에 평균 계획 손익비, 종료된 기록 기준 최대 낙폭, 판정/진행/모호 표본 수를 추가했습니다.
- 기록 전체를 JSON으로 백업하거나 CSV로 내보낼 수 있습니다. 브라우저 localStorage의 기존 기록은 그대로 읽습니다.

이 단계에서는 과거 백테스트나 모델 성능 재검증을 수행하지 않았고, 기존 전략 점수·임계값·후보 수를 변경하지 않았습니다.

### 리빌딩 1단계 — 시장국면 + Forward Paper Ledger

- BTC 4시간 마감봉으로 상승·하락·횡보와 변동성 국면을 표시합니다.
- 시장국면은 아직 점수에 가감하지 않고 각 후보의 `시장 흐름 우호/역행` 설명과 기록에만 사용합니다.
- 페이퍼 기록은 LONG/SHORT 계획을 모두 판정하고 신호 당시 전략·전망·국면·손절·목표를 고정합니다.
- 1·3·6·24시간 뒤 실제 가격 경로, 비용 반영 R, MFE/MAE와 종료 시각을 보존합니다.
- 같은 1시간봉에서 손절과 목표가가 모두 닿으면 순서를 추측하지 않고 모호 사례로 분리합니다.

이 단계의 목적은 점수를 더 높이는 것이 아니라, 국면별 실제 결과를 쌓아 다음 재학습과 전략 제거 판단에 쓸 근거를 만드는 것입니다.

**로컬 연구실:** `lab.cmd all`로 과거 데이터 수집·전략 비교 성적표를 만들고 `lab.cmd serve`로 확인합니다. 공개 API만 사용하며 실제 주문은 없습니다. [설치·실행·모의 기록 안내](research/lab/README.md)

[2026-09-16 지표 점검·보완 보고서](docs/INDICATOR_REVIEW_2026-09-16.md): 마감 봉/캐시 처리, 확률 입력 검증, CRT 및 확률 자동 만료, 승률 설명 수정과 남은 검증 과제.

기존 후보에 **CRT + TBS** 확인을 추가했습니다. `CRT + TBS 확인만` 필터와 상세의 전용 손절·중앙/반대편 목표를 사용할 수 있습니다. 마감된 4시간 범위와 5분 몸통 이탈·복귀·전환을 사용하며 아직 승률을 검증하지 않은 실험 기능입니다. [정확한 규칙과 사용법](docs/CRT_TBS.md)

1. Binance Futures 전체 USDT 무기한 종목을 불러옵니다. (공개 REST API)
2. 24시간 거래대금·거래횟수로 유동성 상위 종목을 추립니다.
3. 급락·저점 근접·과매도 회복 후보를 1시간봉으로 빠르게 걸러냅니다.
4. 남은 후보를 4시간·1시간·15분·5분 멀티타임프레임으로 정밀 분석합니다.
5. 시장구조(BOS/CHoCH), 유동성 스윕, FVG·오더블록, 거래량/Delta, 매도 흡수를
   종합해 **0~100점**으로 점수화하고 **1~5단계**(매집→유동성 회수→구조전환→진입→추격 금지)로 분류합니다.
6. 후보를 클릭하면 로그인된 TradingView 차트로 연결합니다.

방향은 **롱**(급락·과매도 반등), **숏**(급등·과매수 반락), **양방향**을 지원합니다.
숏은 롱의 대칭 — 고점 유동성 스윕·하락 구조전환·bearish FVG/OB·매수 흡수로 평가합니다.
양방향은 종목별로 롱/숏 중 높은 점수 쪽을 표시합니다.

### 스캔 모드 3종

필터에서 **전체 스캔 (3개 모드)** 을 선택하면 아래 세 스캐너를 한 번의 실행으로
순차 검색합니다. 결과는 같은 화면에서 모드별로 묶이며 각 행과 모바일 카드에
`급락 반등`·`조기 포착`·`급등 후 급락` 출처 배지가 표시됩니다. 같은 종목이 여러
모드에 잡히면 전략별 방향·점수·계획이 다르므로 합치지 않고 각각 표시합니다.

- **급락 반등**(기본) — 위 파이프라인. 크게 떨어진 것의 되돌림을 노립니다.
- **조기 포착** — 크게 오르기 전 구간을 노립니다. 4시간봉에서 **14일 추세 강도 +
  24시간 변동 + 최근 상장**으로 채점해 **관찰 → 임박 → 돌파** 3단계로 분류합니다.
  중형 중심(거래대금 5M↑, 상위 200, 대형코인 제외), 롱 전용. 이 모드에서는 방향·노이즈
  필터를 자동으로 우회합니다.

  > 이 기준은 감이 아니라 데이터로 정했습니다. 529종목 × 일별 평가 **57,720행**을 시간순
  > 70/30 으로 나눠 학습셋에서만 모델을 고르고 검증셋에서 한 번 확인했습니다.
  > 라벨은 "이후 7일 안에 24시간 +40% 이상". 원래 전제(변동성 압축·거래량 고갈)는
  > 표본 외 검증에서 리프트가 기준선 아래로 흩어져 게이트와 채점에서 전부 뺐습니다.
  > 미결제약정·펀딩비도 다변량에서 계수가 죽어(모멘텀의 대리변수) 제외했습니다.
  > 검증셋 상위 3종목/일 기준 리프트 **10.71x**.
  >
  > **점수 구간별 실측 적중률** — 70점+ 29%, 55~69 16%, 40~54 12% (무작위 3.57%).
  > 화면의 "급등확률" 이 이 숫자입니다. 발동해도 대부분은 급등하지 않습니다.
  > 언제 오를지는 알 수 없는 **후보 좁히기** 도구이며 단독 매매 근거로 쓰지 마세요.
  >
  > **급등한 뒤에도 대부분 되돌립니다.** 급등 141건의 고점 이후 5일을 추적한 결과 중앙값
  > **82%를 반납**했고 31%는 전량 반납했습니다. 상승폭의 절반 미만만 반납한 경우는 10.6%뿐입니다.
  > 급등 후 버틸 종목을 사전 지표로 구분할 수 있는지도 확인해 봤지만(거래대금이 유일하게
  > 유의미한 방향이었음) 실제 채점에 넣었을 때 효과가 노이즈 수준이라 넣지 않았습니다.
  > 표시되는 목표가는 분할 익절을 전제로 보세요.

- **급등 후 급락** (`pump_fade`, SHORT 전용) — 1시간 마감봉 기준 6시간 +12% 또는
  24시간 +25% 급등을 먼저 확인합니다. 이후 15분 거래량 클라이맥스·긴 윗꼬리·고점
  sweep 실패·Taker Buy 소진·EMA20/VWAP 하향 이탈과 5분 구조 붕괴를 평가해
  **1 과열 감시 → 2 고점 거절 → 3 급락 확인**으로 분류합니다. 고점 대비 12% 이상
  하락한 후보는 늦은 숏 위험으로 감점하고, 손절 거리가 8% 이상이면 계획을 무효화합니다.
  점수와 임계값은 실제 데이터 검증 전 **EXPERIMENTAL**이며 급락 확률이 아닙니다.
  이 모드에서는 시드·레버리지·금액 계산을 사용하지 않습니다.

### 24시간 방향 확률 전망

세 스캐너의 점수와 별도로, 최종 후보마다 **상승·하락·횡보 확률**을 표시합니다.
질문은 “수익이 나는가?”가 아니라 다음과 같이 고정합니다.

> 마감된 4시간봉 이후 24시간 안에 그 마감가 기준 변동성 경계
> `±clamp(1.5 × ATR14%, 2%, 8%)` 중 어느 쪽을 먼저 건드리는가?

상승·하락·횡보는 합계 100%이며, 같은 미래 봉에서 양쪽 경계를 모두 건드린 과거 표본은
선후를 알 수 없어 학습에서 제외합니다. 코인 자체의 가격·RSI·EMA·변동성·거래량뿐 아니라
같은 시점의 BTC 흐름도 입력합니다. BTC 4시간봉은 스캔당 한 번만 받고, 각 코인의 4시간봉은
기존 분석 데이터를 재사용합니다. `pump_fade`만 급등 1차 필터 통과 후보에 한해 4시간봉을
추가 조회합니다.

이 숫자는 **TP/SL 도달률·수익 확률·매수/매도 지시가 아닙니다.** 현재 거래 중인 종목의 최근
약 166일 데이터만 사용해 상장폐지 종목과 여러 시장 국면이 빠져 있습니다. 시간순 검증의
최종 시험에서 단순 기준선보다 나쁜 모델은 활성화하지 않으며 화면에는 `산출 보류`로 표시합니다.
현재 배포 모델은 시간순 시험 15,093건에서 log loss **1.0769**(단순 기준선 **1.0813**),
Brier **0.6520**(기준선 **0.6551**), accuracy **42.04%**(다수 클래스 기준선 **41.38%**)로
게이트를 통과했습니다. 차이는 작으므로 확신 신호가 아니라 보수적인 보조 정보로 봐야 합니다.
재현 코드는 `research/train-direction-model.mjs`, 상세 정의는
`docs/superpowers/specs/2026-08-26-direction-probability-forecast-prd.md`에 있습니다.

## 사용법

1. 상단 **스캔 시작** 버튼을 누르면 파이프라인이 실행됩니다.
2. 진행률 바에서 단계(종목 수집 → 유동성 필터 → 1차 분석 → 정밀 분석)를 확인합니다.
3. 결과 목록에서 점수·단계·방향·핵심 신호·손익비를 확인합니다.
4. **상세**를 누르면 점수 근거, 시간봉별 상태, 진입·손절·목표가를 봅니다.
5. **TV / TradingView에서 타점 확인**을 누르면 새 탭에서 차트가 열립니다.
6. 필터 영역에서 방향·최소 점수·거래대금·단계·정렬을 조정하고 **필터 적용**을 누릅니다.
   설정은 `localStorage`에 자동 저장됩니다.
7. **자동 갱신**을 켜면 일정 주기(기본 90초)로 재스캔하며 "다음 갱신까지 남은 시간"이 표시됩니다.
   탭이 백그라운드로 가면 주기가 자동으로 느려집니다.(§18) 주기는 `js/config.js`의 `refresh.intervalMs`에서 조정합니다.

### 리페인트(미래 참조) 방지

기본 점수는 **마감 캔들**만 사용합니다. 진행 중 캔들을 포함한 실시간 예상 신호를 보려면
설정에서 별도로 켤 수 있으며, 이 경우 신호는 실시간 추정으로 구분됩니다.
모든 지표는 과거 데이터만으로 계산되며 미래 데이터를 참조하지 않습니다. 기존 계산은
`tests/repaint.test.js`, pump_fade는 미래 5분봉 차단과 prefix 불변성 테스트로 검증합니다.

## GitHub Pages 배포

이 폴더(`qar-ict-scanner/`)를 저장소 루트 또는 하위 경로에 그대로 올리면 됩니다.
모든 경로가 **상대경로**라 하위 경로에서도 동작합니다.

### 방법 A — 저장소에 직접 배포

```bash
cd qar-ict-scanner
git init
git add .
git commit -m "QAR ICT Early Scanner"
git branch -M main
git remote add origin https://github.com/<사용자명>/<저장소명>.git
git push -u origin main
```

그다음 GitHub 저장소에서:

1. **Settings → Pages** 이동
2. **Source**를 `Deploy from a branch`로 선택
3. **Branch**를 `main` / `/ (root)`로 선택하고 저장
4. 잠시 후 `https://<사용자명>.github.io/<저장소명>/` 에서 실행됩니다.

> 이 폴더를 저장소의 하위 폴더(예: `docs/`)에 두었다면 Pages Source를 `main` / `/docs`로 지정하세요.

### 방법 B — 로컬 미리보기

정적 파일이지만 ES 모듈은 `file://`에서 로드되지 않으므로 로컬 서버가 필요합니다.

```bash
# Python
cd qar-ict-scanner
python -m http.server 8123

# 또는 Node
npx --yes serve -l 8123 .
```

브라우저에서 `http://localhost:8123/` 접속.

### pump_fade 오프라인 연구

운영 가중치를 바꾸지 않고 6시간 12/15%와 24시간 25/30% 조합을 시간순 60/20/20,
6시간 purge로 비교합니다. 같은 5분봉에서 목표와 손절을 모두 건드리면 `AMBIGUOUS`,
자료 구간이 비면 `INCOMPLETE`로 분리합니다.

```bash
node research/pump-fade-backtest.mjs --help
node research/pump-fade-backtest.mjs --input dataset.json --output report.json
```

## 설계 원칙

- 백엔드 없이 GitHub Pages에서 실행되는 정적 웹앱
- Vanilla HTML/CSS/JS ES Modules, 모든 경로 상대경로
- Binance 공개 REST만 사용, 개인 API 키·자동 주문 없음
- 모든 가중치·필터 임계값은 `js/config.js`에서 조정 가능
- 계산은 재현·테스트 가능하게 분리, 미래 데이터 참조(lookahead) 금지
- 아이폰 Safari(뷰포트/Safe Area/44px 터치/메모리) 고려

## 한계

- 실제 호가창을 복원하지 않습니다. 흡수·Delta는 kline의 Taker Volume 기반 **추정**입니다.
- TradingView 유료·Invite-Only 지표를 복제하지 않습니다. 링크로만 연결합니다.
- pump_fade 임계값·가중치는 초기 실험값입니다. 고정 과거 데이터셋에서 비용·펀딩·
  슬리피지를 포함한 검증을 마치지 않았으므로 성과 우위를 주장할 수 없습니다.
- 점수·단계·손익비는 참고 지표이며 매매 신호가 아닙니다.
