# QARScanner + TradingView 판정 정합성 안정화 PRD

작성일: 2026-07-27
대상 저장소: `ddanghae/QARScanner`
상태: 구현·자동검증·TradingView 컴파일 완료 / 롱·숏 발생 화면 추가 관찰 필요

## 1. 문제

QARScanner는 전체 Binance USD-M 종목에서 후보를 찾고, TradingView Pine 지표는 선택한 종목의 타점을 확인하는 역할이다. 현재 역할 분리는 적절하지만 다음 불일치가 있다.

1. Pine 기본값 `useEntryTiers=true`가 `longPrecisionReady` / `shortPrecisionReady`를 우회한다. 화면에는 "정밀 (추천)"이라고 표시되지만 실제 최종 타점은 정밀 순서·연결 구간·반응봉·변동성·추격 제한을 요구하지 않을 수 있다.
2. QAR reversal 단계 분류는 2~5단계 어디에도 해당하지 않으면 무조건 1단계 "관찰 초기"를 부여한다. 실제 근거 부족과 초기 매집을 구분하지 못한다.
3. QAR의 보통 흡수와 강한 흡수가 최종 점수에서 모두 같은 10점을 받는다.
4. QAR의 5단계 "늦음·추격 금지" 결과도 총점만 높으면 기본 결과에 노출될 수 있다.
5. QAR의 `score`/`stage`와 Pine의 14점/1~5등급이 같은 의미처럼 보이지만 서로 독립된 휴리스틱이다.
6. 현재 Pine 원본이 QARScanner 저장소에서 버전 관리되지 않아 웹 스캐너와 차트 지표의 릴리스 정합성을 추적하기 어렵다.

이번 작업은 정확도나 승률을 새로 주장하지 않는다. 먼저 코드의 설명과 실제 판정이 일치하도록 만들고, 이후 성과 기반 튜닝이 가능한 기준점을 만든다.

## 2. 성공 기준

1. Pine에서 "정밀" 타점은 반드시 정밀 조건을 모두 통과한 뒤 등급 기준을 적용한다.
2. 등급 모드는 정밀 판정을 대체하지 않고 통과한 후보의 품질 라벨로만 동작한다.
3. QAR reversal 결과에서 근거 부족은 `stage=0`으로 명시되고 실제 1단계와 구분된다.
4. 보통 흡수와 강한 흡수가 서로 다른 점수를 받는다.
5. `stage=5`는 기본 목록에서 숨겨지고 사용자가 명시적으로 선택할 때만 볼 수 있다.
6. UI에서 세 점수 체계를 `셋업 점수`, `진행 단계`, `차트 정합 등급`으로 구분한다.
7. Pine canonical source와 수동 검증 기록이 저장소에 포함된다.
8. 기존 reversal/early 모드와 관련 테스트가 모두 통과한다.
9. TradingView Pine Editor에서 컴파일되고 15분봉 기준 롱·숏 샘플을 각각 확인한다.

## 3. 범위

### 3.1 Pine 판정 수정

- 첨부된 `쉬운 시장 흐름 + 코인 찾기 [v3.3]`를 저장소의 canonical source로 추가하고 버전을 `v3.4`로 올린다.
- 기존 `useEntryTiers=true` 우회 문제를 제거하고, 단일 선별 모드에서 등급 결합 모드를
  선택했을 때 최종 타점 조건을 다음 의미로 변경한다.

```text
정밀 셋업 통과 AND 최소 차트 정합 등급 통과
```

- 롱·숏에 동일한 규칙을 적용한다.
- 설정 문구에서 등급이 확률이나 보장된 신뢰도가 아님을 명시한다.
- 알림과 계획선은 수정된 최종 타점에서만 시작한다.
- 마감봉, TP/SL 동일 봉 순서 불명 처리, 자동 주문 금지 경계는 유지한다. MTF는 요청
  시간봉이 현재 차트보다 높을 때만 `[1] + lookahead_on` 확정값을 사용하고, 동일 시간봉은
  현재 차트 상태를 직접 계산해 불필요한 1봉 지연을 만들지 않는다. 하위 시간봉 요청은 차단한다.

### 3.2 QAR 단계 판정 수정

- reversal 모드에 `stage=0`, key `insufficient`, label `근거 부족`을 추가한다.
- 1단계는 최소한 초기 관찰 근거를 명시적으로 충족할 때만 부여한다.
- early 모드의 기존 1~3단계 의미는 변경하지 않는다.
- UI 단계 필터와 배지를 모드별로 맞춘다.

초기 1단계 조건은 다음 중 두 가지 이상 충족으로 구현한다.

- 급락/급등 및 RSI 조건
- 최근 저점/고점 근접
- 거래량 반응
- 방향성 CVD/Delta 개선
- FVG 또는 OB 생성

이 조건은 기존에 계산한 필드만 재사용하며 새 외부 데이터 호출을 추가하지 않는다.

### 3.3 흡수 점수 수정

- `estimateAbsorption()`의 기존 결과를 최종 점수에 반영한다.
- 근거 부족: 0점
- 보통 흡수: 가중치의 60% (기본 6점)
- 강한 흡수: 가중치의 100% (기본 10점)
- 설정된 `sellAbsorption` 가중치가 바뀌어도 비율로 계산한다.

### 3.4 추격 금지 기본 제외

- `stage=5` 결과는 계산과 상세 근거에 남긴다.
- 기본 목록에서는 제외한다.
- 사용자가 `5 늦음·추격 금지` 필터를 명시적으로 선택하면 조회할 수 있다.
- 점수 계산 자체를 삭제하거나 0점으로 강제하지 않는다.

### 3.5 용어와 설명 정리

- QAR `score`: `셋업 점수`
- QAR `stage`: `진행 단계`
- Pine tier: `차트 정합 등급`
- `신뢰도`, `확실한 것`, `거의 완벽`처럼 확률로 오해될 표현은 제거한다.
- 점수와 등급이 성공 확률이 아니라 규칙 충족 정도임을 UI와 README에 명시한다.

### 3.6 버전 관리 및 TradingView 적용

- 저장소에 `tradingview/easy_market_flow_v3_4.pine`을 추가한다.
- `tradingview/VERIFY.md`에 컴파일 및 샘플 검증 결과를 기록한다.
- 로컬 검증 후 로그인된 TradingView Pine Editor의 기존 지표를 수정한다.
- 저장 전 기존 TradingView 소스를 로컬 백업하거나 TradingView 버전 이력을 확인한다.

## 4. 비범위

- 자동 주문, 계정, 포지션, 레버리지, API 키 연동
- 점수를 승률이나 상승 확률로 변환
- 검증 데이터 없이 전체 가중치 재설계
- Pine에서 QARScanner의 100점 점수를 재계산
- Pine을 다종목 스캐너로 다시 활성화
- early 모드 로직을 Pine에 포팅
- WebSocket 또는 서버 추가
- 과거 신호를 유리한 체결 순서로 가정하는 백테스트

## 5. 제약 조건

1. Binance 공개 데이터와 마감 캔들만 기본 판정에 사용한다.
2. QARScanner는 정적 GitHub Pages 앱 구조를 유지한다.
3. 모든 튜닝값은 `js/config.js`에서 관리한다.
4. 기존 early 모드 결과 shape을 깨지 않는다.
5. Pine은 `indicator()`로 유지하며 주문을 만들지 않는다.
6. QAR 점수와 Pine 등급을 서로 환산하지 않는다.
7. 사용자 소유의 기존 TradingView 지표를 덮어쓰기 전 복구 가능한 사본을 확보한다.
8. 저장소의 기존 사용자 변경과 무관한 파일은 수정하거나 커밋하지 않는다.

## 8. 위험 및 복구

### 로컬 저장소

- 변경은 Git으로 추적되므로 커밋 전 diff 검토와 커밋 단위 되돌리기가 가능하다.
- 기존 main 이력을 재작성하지 않는다.

### TradingView 외부 변경

- Pine Editor의 기존 스크립트 저장은 외부 상태 덮어쓰기다.
- 적용 전 기존 v3.3 원문을 저장소에 보존한다.
- 가능하면 새 이름 `쉬운 시장 흐름 + 코인 찾기 [v3.4]`로 사본을 저장해 v3.3을 유지한다.
- 동일 스크립트에 덮어써야 한다면 TradingView 버전 이력 복구 가능 여부를 먼저 확인한다.

### 동작 변화

- 정밀 타점 수가 줄어드는 것은 예상된 변화다.
- 이는 정확도 향상이 검증되었다는 뜻이 아니라 설명과 실제 조건을 일치시킨 결과다.
