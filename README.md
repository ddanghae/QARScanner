# 마켓 스캐너

## W 패턴 탭

사이드바 **W 패턴**에서 15분봉·1시간봉을 독립 탐색합니다. 첫 V 회복은 **관심**, 첫 저점을 지킨 두 번째 지지는 **타겟**, 돌파 검증과 다음 봉 종가 유지까지 확인하면 **타점**입니다. 가짜 W 검증 필터, 상승 중 W 포함 설정, 제외 사유, 차트와 확인 시각을 제공합니다. 타점은 확인 봉의 종가이며 주문 체결가가 아닙니다.

상위 50/100/200종목을 선택해 **시장 스캔**을 누르세요. W 탭은 처음 열 때 로드되며 탭을 바꿔도 조회 결과를 유지합니다. 숨겨진 W 탭의 자동 조회는 일시 정지합니다. W 탭 사용 중에는 기존 스캐너 자동 갱신을 잠시 멈추고, 기존 자동 갱신 설정은 복귀 시 유지합니다. 진행 중인 조회는 완료까지 기다려 두 스캐너의 요청이 겹치지 않게 합니다.

느린 두 번째 반등, 제한된 재돌파, 첫 저점을 지키는 바닥 재형성을 추적합니다. 돌파 확인 타점과 실제 넥라인 재지지 타점은 따로 표시합니다. 거래대금 순위에서 빠진 진행 중 후보도 페이지가 열린 동안 계속 추적합니다.

필터 수치는 초기 설계값이며 검증된 승률이 아닙니다. [정의·출처·필터 상세](docs/W-PATTERN.md)를 참고하세요. `npm test`에 W 탐지·관심 추적·탭 연동 검사가 포함되어 있습니다.

## 현재 버전: 기본 / 공격적 패턴 탐색

### 새 탭: 추세·수급

공격적 탐색 결과에는 **한 번 더 걸러내기** 버튼이 있습니다. 전체 / 방향 일치 / 타점 조건 / 타점 근접을 선택하면 기존 결과를 재스캔 없이 좁히고 탭별 개수를 함께 갱신합니다. 선택은 브라우저에 저장됩니다. 방향 일치는 종합 방향 근거 70% 이상·같은 방향 적합도 65 이상·최신 1시간 EMA200 일치를 요구합니다. 타점 조건은 유효한 구조 가격과 왕복 비용 0.2% 적용 후 손익비 1.5 이상·손절폭 0.3~8%, 타점 근접은 돌파/반응 뒤 검토 구간 도달까지 요구합니다. 추세·수급 탭은 자체 전환 확인 계획을 사용합니다. 필터는 표시 조건이며 수익성이나 승률을 검증한 기준이 아닙니다. 1시간봉이 누락되거나 조건이 엄격하면 후보가 0개일 수 있습니다. 전체를 누르면 원래 목록으로 돌아갑니다.

- **5분·1시간** 시간봉을 선택해 스캔한 뒤 **추세·수급** 탭을 열면 전체/롱/숏 후보와 **전환 확인만** 필터를 사용할 수 있습니다.
- 1시간 EMA200·확정 고점/저점 구조와 5분 확정 프랙탈이 같은 방향인 지속형 패턴을 대상으로, **마감 돌파 → 첫 눌림 → 다음 봉 이후 종가 전환**을 순서대로 확인합니다. 패턴 가격선은 돌파 전에 고정합니다. 15분 패턴은 선택 시 추가하며 4시간 추세는 참고 정보입니다.
- 전환 확인 후에만 검토 구간·SL·TP1/2/3를 표시합니다. 왕복 비용 0.2% 가정, 비용 후 손익비 1.5 이상, 손절 거리 0.3~8%를 요구합니다. 목표 선도달·구조 무효화·추격·만료 시 검토 구간을 표시하지 않습니다.
- **세력 감지 · 수급 관측**은 거래량, 공격적 매수/매도 비중, Delta/CVD, 흡수 추정, 고점/저점 스윕을 보여줍니다. 활성 상위 10종목만 OI·펀딩을 추가 조회하며 누락은 그대로 표시합니다. 수급 관측은 진입 조건이나 승률에 합산하지 않습니다.
- 이 새 전략의 실전 성과는 아직 검증하지 않았습니다. 동작 검사는 수익성 검증과 다릅니다. 규칙과 비용 가정은 [패턴 안내](docs/CHART-PATTERNS.md#추세수급-리테스트)를 확인하세요.

현재 실행 화면은 차트 패턴 스캐너입니다. 아래의 과거 전략 설명은 연구 이력이며 현재 실행 모드 목록과 다릅니다.

- **기본**: 거래대금 20M USDT, 100종목, 피벗 깊이 3. 기존 방향 가중치·진입 조건 유지.
- **공격적**: 선택 시 거래대금 5M USDT, 최대 200종목, 피벗 깊이 2. 유동성 조건을 통과한 관심 종목·거래대금·등락 확대·거래활동을 섞어 탐색합니다. 거래량 급증과 봉 변동폭 확대는 수집한 마감 봉에서 추가로 살펴봅니다.
- 설정의 **탐색 성향 → 공격적**을 선택하고 **스캔 시작**을 누르세요. 프로필 선택은 거래대금·검사 범위를 프리셋 값으로 바꾸며 이후 개별 조정도 가능합니다.
- **조기 관찰** 탭은 형성 중인 단기 패턴이나 거래량 변화 후보를 먼저 보여줍니다. 후보 표시와 진입 구간은 별도입니다. 기존 방향·적합도·손익비 1.5·구조 가격 조건을 만족해야 진입 구간이 나옵니다.
- 공격적 탐색은 진행 중 봉 옵션과 무관하게 마감 봉만 사용합니다. 기존 5분 프랙탈 확인은 피벗 깊이 3을 유지합니다. 공격적 탐색 결과에 기존 기준의 과거 성적을 붙이지 않습니다.
- 자동 갱신을 켜면 전체 탐색은 최소 90초, 상위 20종목의 선택된 5분·15분 시간봉은 30초마다 갱신합니다. 선택된 상위 시간봉은 캐시를 재사용하며 백그라운드에서는 주기를 늘립니다.

## 무엇을 하는가

1. Binance Futures 전체 USDT 무기한 종목을 불러옵니다. (공개 REST API)
2. 24시간 거래대금·거래횟수로 유동성 상위 종목을 추립니다.
3. 급락·저점 근접·과매도 회복 후보를 1시간봉으로 빠르게 걸러냅니다.
4. 남은 후보를 4시간·1시간·15분·5분 멀티타임프레임으로 정밀 분석합니다.
5. 시장구조(BOS/CHoCH), 유동성 스윕, FVG·오더블록, 거래량/Delta, 매도 흡수를
   종합해 **0~100점**으로 점수화하고 **1~5단계**(매집→유동성 회수→구조전환→진입→추격 금지)로 분류합니다.
6. 후보를 클릭하면 로그인된 TradingView 차트로 연결합니다.

방향은 **롱**(급락·과매도 반등), **숏**(급등·과매수 반락), **양방향**을 지원합니다.
숏은 롱의 대칭 — 고점 유동성 스윕·하락 구조전환·bearish FVG/OB·매수 흡수로 평가합니다.
양방향은 종목별로 롱/숏 중 높은 점수 쪽을 표시합니다.

### 스캔 모드 4종

- **급락 반등**(기본) — 위 파이프라인. 크게 떨어진 것의 되돌림을 노립니다.
- **조기 포착** — 크게 오르기 전 구간을 노립니다. 4시간봉에서 **14일 추세 강도 +
  24시간 변동 + 최근 상장**으로 채점해 **관찰 → 임박 → 돌파** 3단계로 분류합니다.
  중형 중심(거래대금 5M↑, 상위 200, 대형코인 제외), 롱 전용. 이 모드에서는 방향·노이즈
  필터를 자동으로 우회합니다.

  > 이 기준은 감이 아니라 데이터로 정했습니다. 529종목 × 일별 평가 **57,720행**을 시간순
  > 70/30 으로 나눠 학습셋에서만 모델을 고르고 검증셋에서 한 번 확인했습니다.
  > 라벨은 "이후 7일 안에 24시간 +40% 이상". 원래 전제(변동성 압축·거래량 고갈)는

  > **점수 구간별 실측 적중률** — 70점+ 29%, 55~69 16%, 40~54 12% (무작위 3.57%).
  > 화면의 "급등확률" 이 이 숫자입니다. 발동해도 대부분은 급등하지 않습니다.

  > **급등한 뒤에도 대부분 되돌립니다.** 급등 141건의 고점 이후 5일을 추적한 결과 중앙값

## 사용법

1. 상단 **스캔 시작** 버튼을 누르면 파이프라인이 실행됩니다.
2. 진행률 바에서 단계(종목 수집 → 유동성 필터 → 1차 분석 → 정밀 분석)를 확인합니다.
3. 결과 목록에서 점수·단계·방향·핵심 신호·손익비를 확인합니다.
4. **상세**를 누르면 점수 근거, 시간봉별 상태, 진입·손절·목표가를 봅니다.
5. **TV / TradingView에서 타점 확인**을 누르면 새 탭에서 차트가 열립니다.
6. 필터 영역에서 방향·최소 점수·거래대금·단계·정렬을 조정하고 **필터 적용**을 누릅니다.
   설정은 `localStorage`에 자동 저장됩니다.
7. **자동 갱신**을 켜면 일정 주기(기본 90초)로 재스캔하며 "다음 갱신까지 남은 시간"이 표시됩니다.
   탭이 백그라운드로 가면 주기가 자동으로 느려집니다.(§18) 주기는 `js/config.js`의 `refresh.intervalMs`에서 조정합니다.

### 리페인트(미래 참조) 방지

기본 점수는 **마감 캔들**만 사용합니다. 진행 중 캔들을 포함한 실시간 예상 신호를 보려면
설정에서 별도로 켤 수 있으며, 이 경우 신호는 실시간 추정으로 구분됩니다.
모든 지표는 과거 데이터만으로 계산되며 미래 데이터를 참조하지 않습니다. (`tests/repaint.test.js`로 검증)

## GitHub Pages 배포

이 폴더(`qar-ict-scanner/`)를 저장소 루트 또는 하위 경로에 그대로 올리면 됩니다.
모든 경로가 **상대경로**라 하위 경로에서도 동작합니다.

### 방법 A — 저장소에 직접 배포

```bash
cd qar-ict-scanner
git init
git add .
git commit -m "QAR ICT Early Scanner"
git branch -M main
git remote add origin https://github.com/<사용자명>/<저장소명>.git
git push -u origin main
```

그다음 GitHub 저장소에서:

1. **Settings → Pages** 이동
2. **Source**를 `Deploy from a branch`로 선택
3. **Branch**를 `main` / `/ (root)`로 선택하고 저장
4. 잠시 후 `https://<사용자명>.github.io/<저장소명>/` 에서 실행됩니다.

> 이 폴더를 저장소의 하위 폴더(예: `docs/`)에 두었다면 Pages Source를 `main` / `/docs`로 지정하세요.

### 방법 B — 로컬 미리보기

정적 파일이지만 ES 모듈은 `file://`에서 로드되지 않으므로 로컬 서버가 필요합니다.

```bash
# Python
cd qar-ict-scanner
python -m http.server 8123

# 또는 Node
npx --yes serve -l 8123 .
```

브라우저에서 `http://localhost:8123/` 접속.

계산·구조·유동성·점수·리페인트 방지 테스트가 포함됩니다.

```bash
# Node (CI 친화적, 종료코드 반환)
node tests/run.js

# 브라우저
# http://localhost:8123/tests/ 접속
```

현재 32개 테스트 전부 통과합니다. (EMA·RSI·MACD·ATR·Bollinger·VWAP·OBV,
Pivot·BOS·CHoCH, 스윕·FVG, 흡수·단계·점수, prefix==full 리페인트 검증)

## 파일 구조

```
qar-ict-scanner/
├── index.html            # 단일 페이지
├── manifest.webmanifest  # PWA (선택)
├── sw.js                 # 서비스워커 — 앱 셸만 캐시, API 응답은 캐시 안 함
├── css/style.css         # 모바일 우선, 다크모드, 카드/테이블 반응형
├── js/
│   ├── main.js           # 진입점
│   ├── config.js         # 모든 튜닝값 (가중치·감점·필터·TTL)
│   ├── state.js          # 전역 상태 + localStorage 설정
│   ├── api/binance.js    # 공개 REST + 동시요청 제한·큐·재시도·캐시
│   ├── core/             # 순수 계산 모듈 (테스트 대상)
│   │   ├── indicators.js       # EMA/SMA/RSI/MACD/BB/ATR/VWAP/StochRSI/OBV
│   │   ├── volume-analysis.js  # Taker/Delta/CVD/상대거래량
│   │   ├── market-structure.js # Pivot/HH·HL·LH·LL/BOS/CHoCH
│   │   ├── liquidity.js        # Equal H/L·스윕·목표 유동성
│   │   ├── fvg.js              # FVG (open/partial/filled/inverse)
│   │   ├── order-block.js      # 오더블록 (자체 규칙)
│   │   ├── risk-reward.js      # 진입·손절·TP·손익비
│   │   └── scoring.js          # 흡수 추정·단계 분류·100점 점수
│   ├── scanner/
│   │   ├── prefilter.js        # 1~3단계 필터
│   │   ├── deep-scanner.js     # 멀티타임프레임 정밀 분석
│   │   └── scan-controller.js  # 파이프라인 오케스트레이션
│   └── ui/
│       ├── dashboard.js, detail-panel.js, settings.js,
│       ├── notifications.js, tradingview.js, format.js
└── tests/                # harness + 5개 테스트 스위트 + 브라우저 러너
```

## 설계 원칙

- 백엔드 없이 GitHub Pages에서 실행되는 정적 웹앱
- Vanilla HTML/CSS/JS ES Modules, 모든 경로 상대경로
- Binance 공개 REST만 사용, 개인 API 키·자동 주문 없음
- 모든 가중치·필터 임계값은 `js/config.js`에서 조정 가능
- 계산은 재현·테스트 가능하게 분리, 미래 데이터 참조(lookahead) 금지
- 아이폰 Safari(뷰포트/Safe Area/44px 터치/메모리) 고려

## 한계

- 실제 호가창을 복원하지 않습니다. 흡수·Delta는 kline의 Taker Volume 기반 **추정**입니다.
- TradingView 유료·Invite-Only 지표를 복제하지 않습니다. 링크로만 연결합니다.
- 점수·단계·손익비는 참고 지표이며 매매 신호가 아닙니다.


## 개발·검증 하네스

Node.js 20 이상에서 `npm test`로 문법, 미리보기 경로, 앱 테스트를 한 번에 실행합니다. `npm run serve`는 정적 웹앱을 로컬에서 미리 보여줍니다. 자세한 내용은 [docs/HARNESS.md](docs/HARNESS.md)를 참고하세요.
